# Shared step script; screens align by step index. `next` = wait for a new, settled screen.
#
# Steps 0..8 and the guard pairs are gameplay_probe.txt's path, verbatim: the controller-
# configuration 'save to memory card?' dialog lands on a step index that moves with how many
# controller-configuration screens the boot shows, so every step it can land on carries an
# ifref pair (RIGHT moves the highlight YES -> NO, then CROSS answers NO; a blind CROSS = YES
# and the probe then loops on slot select / 'overwritten data will be lost'). ifref presses only
# on a match, so an unused pair costs ~2 s and no press. Rows 47..62 of the 160x112 thumbnail
# are the dialog text only (63..75 are the YES/NO buttons), so the second guard of a pair still
# matches after the RIGHT. Measured on this binary (logs/parity/gate/tfix1, tfix2 and
# hostdraw_fix/mission.drive.log, 2026-09-11): dist 0.00 on the prompt at steps 9/10, 25.7..33.0
# on every screen the later pairs saw; threshold 8.
#
# Without those guards this script stalled on the dialog at step 9 and never reached the
# briefing -- and because black_rows.py counted black frames from anywhere in the run, the
# transition gate went on passing on the boot's black screens (STATUS 2026-09-11).
#
# Step 11 is the burst this script exists for. Answering NO at step 10 takes the game straight
# to the black screen before the mission briefing, so the burst starts on the NO press and
# captures that screen at 5 fps (runs tfix1/tfix2: the fade is at t=54..70 s, w11/w12, 4 frames
# at 1 Hz -- the burst turns those into tens). gate.first_burst_step() finds this step by name
# and score_transition counts ONLY frames from it on, so the boot's black screens cannot stand
# in for the transition.
