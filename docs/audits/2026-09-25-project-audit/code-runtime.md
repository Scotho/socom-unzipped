## Answers to the eight questions, in short

1. **Census** (tracked `.cpp/.h/.c` under `third_party/ps2recomp`, generated VU code excluded): 665 matching lines for
   `TODO|FIXME|XXX|HACK|stub|not implemented|unimplemented|unsupported` (case-insensitive). Word counts: TODO 23 lines
   of prose (plus 129 `TODO_NAMED(...)` call sites), FIXME 0, XXX 0, HACK 5, stub 193, unimplemented 27, unsupported
   17, "not implemented" 0. Top files: `Kernel/Stubs/Audio.cpp` 90, `ps2xTest/src/runtime_state_tests.cpp` 46,
   `ps2_runtime_kernel_tests.cpp` 42, `ps2xRecomp/src/lib/ps2_recompiler.cpp` 39, `ps2_runtime.cpp` 24,
   `ps2_recompiler_tests.cpp` 23, `Kernel/Stubs/Helpers/Support.h` 19, `Kernel/SchedTrace.cpp` 19, `LibC.cpp` 17.
   Game-visible ones: the 20 toml-bound stubs that throw (F1), COP0/FCR/VU control registers the recompiler answers 0
   (F2), `snd989_mixer.cpp:1403` "LFO, XREF, plugins: not modelled", `MPEG.cpp:625` "TODO this resolution should
   follow runtime resolution", `LibC.cpp:761` "TODO: Add translation for PS2 paths like mc0:, host:, cdrom:".
2. **Stub/HLE surface:** `ps2_call_list.h` lists **122 syscalls** (lines 7-141) and **553 EE stubs** (lines 142-700);
   26 `Kernel/Stubs|Syscalls/*.cpp` files define 685 handler functions; **128 handlers are `TODO_NAMED` bodies that
   throw** (129 call sites with the generic `TODO`); the IOP side is 11 module files, of which SOCOM's profile uses 3 plus 3 core ones and 5 (3,133 lines)
   serve other games (F24). Knob registry: 152 names (18 Shipping, 1 Switch, 125 Dev, 8 Test); the only HLE a
   player can switch is `PS2X_SOCOM2_PAD`; the rest are instruments or A/B levers (F31).
3. **Overrides file:** 2,846 lines; 14 sections; ~62 % of it (1,766 lines) is diagnostics, not overrides (S1). It
   carries 54 guest-range hex literals (39 distinct values; 20 in the 8-digit form in code), 57 `+0x..` offsets (42
   distinct), 29 `replaceFunction` call sites and 2 `bindAddressHandler`. Of the ~36 function addresses it hooks
   through `socom2_addresses.h` plus its 8 loader literals, **6 have a name in `recomp/socom2_names.csv`**; research/50
   §4b names four of its struct offsets (F13, F14).
4. **Dead/duplicated:** every tracked source file is reached by some CMake target (checked by basename and glob), and
   no tracked header is unincluded; the dead weight is by *target*, not by file: Vita/Android CMake (F20),
   `rajdhani_bold.h` (F21, verified), other games' IOP modules (F24), a nested upstream workflow (F26), a duplicated
   Ghidra script (F27), an unread tracked toml (F28). The four `recomp_run*.log` and `*.raw.*` files exist only in the
   main tree and are git-ignored (F29).
5. **Build hygiene:** F32-F44. `bootstrap_windows.sh` pins version **and** sha256; CMake's FetchContent and FFmpeg do
   not. CI never compiles `game_overrides_socom2.cpp`. The Linux runner has no tracked test.
6. **Upstream divergence left undone:** F45-F49.
7. **Performance:** instruments exist (F50); no tracked benchmark, budget or fps bar anywhere (F51).
8. **Launcher:** 9 pages, 19 persisted settings plus mappings; one dead preset; no TODOs (F52-F55).

## 2. Structure notes

- **`game_overrides_socom2.cpp` has outgrown its name.** 2,846 lines in 14 sections; by line range, the overrides
  proper are the HLE handlers (79-440), the loader and CD image (442-615), the RtNet port shift (1452-1530), the OSK
  prefill (1532-1597), the chat bounds (1598-1760) and `applySocom2` (2174-2318), about 1,080 lines. The rest, about
  1,766 lines (62 %), is diagnostics: the PC sampler, watch, peek and trigger (617-865), the RDRAM dump (866-915), the
  crash handler for Windows and POSIX (918-1128), the call trace (1149-1380), the music trace (1382-1450), seven
  render traces (1765-2170) and the host profiler (2320-2846). The crash handler and host profiler are generic runtime
  facilities (F22). A `socom2_diagnostics.cpp` and a runtime-side `host_prof.cpp` would leave a file whose name says
  what it holds.
- **The per-revision discipline is good and half done.** `socom2_addresses.h` (450 lines, a column per revision,
  `require()` refusing an unplaced field, a suite that fails on a loader address in it) is the right shape, and the
  loader-literal exemption is argued in a comment (`game_overrides_socom2.cpp:2238-2241`). What sits outside it (F12,
  F17, the camera/node/music offsets of F14) is small and listed in research/61 §3.
- **Two build pipelines for one job.** `build.sh recomp` (r0001, rewrites the tracked map, F32) and
  `scripts/build_revision.sh` (any revision, map as a build product, step markers, provenance sidecar) do the same
  thing with different hygiene. Making `build.sh recomp` call `build_revision.sh r0001` steps 0 and 4 would retire
  F32 and give r0001 the `.complete` markers. Both hard-code `ps2_recomp.exe` (`build.sh:50`,
  `build_revision.sh:391`); Linux has a third script, `scripts/build_linux.sh`.
- **Vendored upstream material nobody owns:** a nested workflow (F26), `CMakeSettings.json` (a Visual Studio preset
  for an MSVC build the project never uses), upstream's `README.md` inside `third_party/ps2recomp`, the games
  database (`games_database.cpp`, 803 lines of every PS2 title, used for one window-title lookup at `src/main.cpp:287`),
  other games' IOP profiles (F24), the Vita/Android CMake (F20), a duplicated Ghidra script (F27).
- **Every tracked source file reaches a target, and no header is orphaned** (checked by basename against every
  CMakeLists and every glob root, and every tracked `.h` against every `#include`). Dead weight here is by
  configuration and target, not by stray file.
- **The stub surface is honest about itself.** `TODO_NAMED` throws with the stub's name, PC, RA and arguments
  (`Unimplemented.cpp:11-48`), and 108 of the 128 throwing bodies are libraries SOCOM does not bind (the `sceSynth*`
  family alone is 75). The risk is only the 20 that the toml does bind (F1).
- **Misleading names for a stranger:** `socom2.toml` "Generated by ElfAnalyzer" (F30); `socom2_ghidra.toml` beside
  the real map (F28); `sound_update_stub.cpp` is a LOTR service, not a SOCOM stub (F24); `build-clang/` is the
  developer tree and `build-release/` the release tree, both under the vendored directory.
- **CI is well built for what it proves** (pinned action SHAs, a docs-only fast path that reports success, no
  cancel-in-progress, the leak scan) and says in its header that it proves nothing about the game. The gap is what
  it could cheaply prove and does not: a compile of the overrides file (F7), pinned Python packages (F40).

## 3. Top five

1. **F7, compile `game_overrides_socom2.cpp` and `socom2_crypto.cpp` in CI.** Every SOCOM hook lives in a file that
   only the owner's locked machine ever compiles. An object-library target costs minutes and needs no disc.
2. **F1, find out which of the 20 throwing stubs the game reaches.** One `PS2X_HLE_STATS=1` mission run (knowing
   issue #40's tail-call blind spot), then either a real body or a non-throwing return for each one that is live.
   It is the cheapest way to rule out a crash class that is currently unmeasured.
3. **F4 and F5, the close's two claims.** `sprint-12` is red on both workflows (6 Python failures) while the close
   block says it merges to `main`, and the docs say Sprint 11 is on `main` as `v0.11.0` when PR #49 is still open
   and the tag does not exist. Both are an hour's work, and both are exactly what a stranger checks first.
4. **F13 and F14, put the runtime's own knowledge into the sidecar.** About 30 hook targets have first-hand
   identities in the runtime and no name in `socom2_names.csv`, and four struct offsets named by research/50 are
   still raw in the hooks. It is lock-free, it is the carry both closes wrote down, and it makes the generated files
   the hooks replace readable.
5. **F51, one tracked performance number.** The runtime has eight instruments and no bar. A gate-side read of the
   sampler's FreezeFields line or `[gs-gl stats]` (frames presented per second on the title stage, pinned like the
   other gate inputs) would turn "58-60 fps" from a sentence into a regression check. KNOWN already shows the
   project confusing stalls with network faults.
