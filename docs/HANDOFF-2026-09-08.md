### Horizon protocol fixes that made the 1.50 client work (all committed)
- MUIS answers LobbyExt/0x03 universe query with the ExtraInfo list (0x338 bytes) **and** a
  UniverseNews reply (both `InfoType` bits must complete).
- `NetConnectionInfo` 2-byte alignment pad made unconditional (AccountLoginResponse must be 0xC4
  bytes; the PS2 client sends no CLIENT_HELLO so the server assumed version 108).

- `CreateGameRequest1` Attributes optional (the 1.50 client sends 0xD0 bytes).
- `Game.OnWorldReport(MediusWorldReport0)` copies `GameStats` (the 1.50 client keeps map/rounds
  there; without it joiners see "unknown" and refuse).
Method for any new "Unhandled Medius Message": find the client handler by id (handler id N of a
class = the N-th `FUN_0063c8a0(slot, class, cb)` registration from decomp line 564046; the handler
returns its expected byte count), read PINE (`tools_py/parity/pine.py`) for live ids.

### RESOLVED (2026-09-08 00:40) — root cause was the frozen COP0 Count, not the socket
Traced with PS2X_CALL_TRACE + PS2X_PEEK: after CONNECT_COMPLETE the SCERT state reaches 8, the
connected callback chain (FUN_00636d58 → FUN_00617250 → FUN_00647108 → game FUN_00300800) runs,
and the game queues the universe query (RtSend type 0x0b, 38 bytes) into the SCERT send ring. The
ring is only written to the socket by the send pump FUN_00634dd8 when "≥30 ms since the last
flush" (conn+0x40 interval, timer at conn+0x20) — and SCE-RT's clock (FUN_0063db68, seconds/usec
at 0x676430) is built on `mfc0 Count`, which the recomp emits as a plain read of ctx->cop0_count
that nothing ever advanced. Pre-connect messages bypass that gate, which is why the handshake
worked. Fix: `PS2Runtime::refreshCop0Count` (host steady clock × 294.912 MHz) at every syscall and
scheduler switch-in. Result: universe query → two SERVER_APP replies → CLIENT_DISCONNECT, and the
exe shows SELECT UNIVERSE ("SOCOM II Local", news text), parity 98.5 vs the PCSX2 golden.
