## 1. PCSX2 online validation — the reference benchmark (setup, results)

PCSX2 is both the reference client and the working proof that the local Horizon server plays a full
online match. The harness in `tools_py/parity/` drives PCSX2 and our exe with the same posted-key
scripts and scores screens; `compare.py` writes `docs/parity/REPORT.md`.

### Server (Horizon), always start first
```
cd server && powershell -NoProfile -Command ".\start-servers.ps1"   # delete server/pids.json if it trips on a stale pid
```
Ports: MUIS 10071, MAS 10075, MLS 10078, MPS 10077, DME 10073 TCP, NAT 10070/UDP, DME 50000/UDP.
App id `0x28E8` (10472). Rebuild after C# edits: `dotnet build Horizon.Server.sln -c Release` in
`server/horizon-server` **after stopping the processes** (the running exe locks its output).
Server RSA `DefaultKey` is in `Server.Medius/Config/ServerSettings.cs`; it matches the client's baked
server modulus (verified). Logs: `server/logs/console-{MUIS,Medius,DME,NAT}.log` — slice from the
line count taken before a run.

### PCSX2 networking setup (all git-ignored; templates in `scripts/parity/pcsx2/`)
- DEV9 **Sockets** mode on the host's Realtek adapter, InterceptDHCP on, manual DNS = the host LAN
  IP (was `192.168.2.10`). PCSX2's `[DEV9/Eth/Hosts]` table did NOT work, so a UDP DNS stub
  (`tools_py/parity/dns_stub.py`, run as admin, binds UDP 53) answers the retail hostnames
  (`socom2-prod[.muis].pdonline.scea.com`, `gate1.*.dnas.playstation.org`) with the host IP.
  The Horizon `server/config/*.json` advertise that same host IP (not 127.0.0.1 — the guest can't
  reach loopback).
- DNAS bypass pnach `0F6FC6CF.pnach` (unconditional `jr ra` at 0x2cc670).
- Memcards formatted with `mymcplus`; hold the saved network config ("Setting 1sdf", SCE/Ethernet,
  DHCP auto). **Only the login-screen savestate is valid** (client A = slot 9, client B = slot 5):
  any state saved after network traffic restores with a stuck SMAP TX ring or dead input, and a
  state copied between installs re-probes the memory card and loses the network config.
- Second client `tools/pcsx2_b` = a robocopy of `tools/pcsx2` with `PINESlot 28012`, slot-2 memcard
  disabled, and `0F6FC6CF.clientB.pnach` that shifts the game's fixed UDP ports 3658/3659 → 3660/3661
  (two guests on one host adapter otherwise collide on the host UDP ports).

### Horizon protocol fixes that made the 1.50 client work (all committed)
- MUIS answers LobbyExt/0x03 universe query with the ExtraInfo list (0x338 bytes) **and** a
  UniverseNews reply (both `InfoType` bits must complete).
- `NetConnectionInfo` 2-byte alignment pad made unconditional (AccountLoginResponse must be 0xC4
  bytes; the PS2 client sends no CLIENT_HELLO so the server assumed version 108).
- Briefing-room channel list on the Lobby class (0xEC request, 0x70-byte 0xED entries).
- `CreateGameRequest1` Attributes optional (the 1.50 client sends 0xD0 bytes).
- `Game.OnWorldReport(MediusWorldReport0)` copies `GameStats` (the 1.50 client keeps map/rounds
  there; without it joiners see "unknown" and refuse).
Method for any new "Unhandled Medius Message": find the client handler by id (handler id N of a
class = the N-th `FUN_0063c8a0(slot, class, cb)` registration from decomp line 564046; the handler
returns its expected byte count), read PINE (`tools_py/parity/pine.py`) for live ids.

## 2. Our exe's online netstack — where it stands (the live task)

The recompiled exe now brings SOCOM's SCE-RT network layer up entirely on the host and **completes
the Medius SCERT transport handshake against the real Horizon MUIS** (commit `0bbf3cd`). It needs no
dns_stub — it resolves the hostnames itself.

Path so far: ONLINE → login screen (eznetcnf/eznetctl IOP service + SIF sreg handshake) → resolves
`socom2-prod.muis.pdonline.scea.com` to `PS2X_SOCOM2_SERVER` (default 127.0.0.1) → TCP-connects to
MUIS (10071) → CRYPTKEY_PUBLIC/PEER → CONNECT_TCP → server sends **CONNECT_ACCEPT + CONNECT_COMPLETE**.

**Blocker:** the client reads the 39-byte accept/complete once, then closes the socket **before**
sending the LobbyExt/0x03 universe query. That is the next task.

### Run it
```
cd server && powershell -NoProfile -Command ".\start-servers.ps1"    # no dns_stub needed
PYTHONIOENCODING=utf-8 PS2X_SOCOM2_NET_TRACE=1 \
  python -m tools_py.parity.drive --target ours \
  --script scripts/parity/launch_to_online_ours.txt --out logs/parity/ours_online --seconds 150
# then: tail -n +<preline> server/logs/console-MUIS.log
```
Env: `PS2X_SOCOM2_SERVER=<ip>` and `PS2X_SOCOM2_HOSTS=name=ip,...` steer resolution;
`PS2X_SOCOM2_NET_TRACE=1` logs every socket op.

### The HLE layers already in place (all in `third_party/ps2recomp/ps2xRuntime/src/lib/socom2_*.cpp`
### and `ps2xIOP/src/modules/eznetcnf.cpp`; contract in `docs/research/10-libnetb-rpc.md`)
- **msifrpc** (`socom2_SifSendCmd` sreg echo + init/bind/call/unbind) — libnetb's SIF transport.
- **libnetb** (`socom2_libnetb.cpp`): the simple RPCs (sceInetCreate/Open/Recv/Send/RecvFrom/SendTo,
  Name2Address, interface queries, poll, inetctl events) and the **libnetb_ex** ring path
  (`FUN_002472c8/74f8/7738/7d30/7fe8/79b8/7bd8`) replaced by host **Winsock** (`socom2_hostnet.cpp`).
  cid = host fd + 1; raw sockets answer an ICMP-echo "probe" locally.
- **eznetcnf/eznetctl** IOP service (one "Setting 1" combination, interface always up); DNAS tick
  `FUN_002cc670` reports done.
- **rt_crypt on the host** (`socom2_crypto.cpp`): 512-bit RSA modexp (`FUN_0062b948`), SHA-1 prefix
  (`FUN_0062eec0`), RC4 variant (`FUN_0062a638/5a8/720/7c8`). The fixed client keypair
  (`socom2_rsa_key.h`) was regenerated as a **full 512-bit modulus** — a 511-bit N let the server's
  512-bit RC4 session key exceed N and broke CONNECT_TCP decryption (this was the hard bug).
