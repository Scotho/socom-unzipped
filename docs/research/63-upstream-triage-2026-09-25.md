### #216 Resolve rest-of-RAM heaps to the main thread's stack base. TheTharin, 2026-08-24, open
- Files: `ps2_runtime.h` (ours: 8 commits), `Kernel/Syscalls/System.cpp` (4 commits), `ps2_runtime.cpp`
  (39 commits, +654/-53), `ps2_runtime_kernel_tests.cpp`.
- Claim: `SetupHeap(-1)` and `EndOfHeap` cap the heap at `0x01F00000`, where the retail kernel uses the main stack
  base. That leaves an 832 KB dead zone.
- Ours has the same cap:
  - `System.cpp:593`: `static constexpr uint32_t kDefaultGuestHeapEnd = 0x01F00000u;` (also `:594`, `:599`, `:604`,
    and `:633` in `EndOfHeap`).
  - `ps2_runtime.cpp:132`: `constexpr uint32_t kGuestHeapHardLimit = 0x01F00000u;` (used at `:556`, `:559`,
    `:1745`, `:1751`, `:1941`).
- **NOT OURS, and the fix would be wrong for us.**
  1. **The "dead zone" is not dead here.** Our runtime keeps its own guest-visible pools in it
     (`Kernel/Syscalls/Helpers/State.h:275-289`):
     - the RPC packet pool at `0x01F00000`;
     - the RPC server placeholders at `0x01F10000` (see #217);
     - the TLS pool at `0x01F20000`;
     - the boot-mode block at `0x01F30000`;
     - the async-callback stack floor at `0x01F00000` (`ps2_runtime.cpp:559`).

     Raising the heap end to the stack base would hand those pages to the guest allocator. Upstream has the same
     pools, so the PR has this problem upstream too.
  2. **The path is not reached.** KNOWN.md:17 (Task 19): "`EndOfHeap`/`sbrk` fire 0 times in a run (the game's own
     pool never walks to `sbrk`)". The game's `malloc@0x00194C30` is bound to `guestMalloc` (KNOWN.md:125).
- Test shape, if anyone reopens it. Call `SetupThread(stack=-1, 0x30000)` and then `SetupHeap(base, -1)`, then
  assert that `EndOfHeap() <= kRpcPacketPoolBase`. It passes today, and it would fail with the PR applied. That test
  is the guard to add *before* any heap move.

### #217 Fix synthetic SIF RPC server memory aliasing. GTTeancum, 2026-08-25, open
- Files: `Kernel/Syscalls/Helpers/State.h` (ours: 1 commit), `Kernel/Syscalls/RPC.cpp` (2 commits, +24/-4),
  `ps2_sif_rpc_tests.cpp` (1 commit).
- Claim: placeholder RPC server descriptors live in EE RAM. If the game reuses that memory, `SifCallRpc` copies the
  request to the overwritten `buf`.
- **Ours has the defect, in a wider form:**
  - `State.h:161-165`: `struct RpcServerState { uint32_t sid = 0; uint32_t sd_ptr = 0; };` has no synthetic mark.
  - `RPC.cpp:313-327` (`SifBindRpc`): `serverPtr = rpcAllocServerAddr(rdram);` ... `g_rpc_servers[rpcId] = {rpcId, serverPtr};`
  - `RPC.cpp:332-335`: `client->buf = sd ? sd->buf : 0; client->cbuf = sd ? sd->cbuf : 0;`
  - `RPC.cpp:517-534` (`SifCallRpc`): `auto *server = serverPtr ? ... : nullptr; if (server) { server->client = clientPtr; ... server->rid = 0; if (server->buf != 0u && ...) rpcCopyToRdram(rdram, server->buf, sendBuf, sendSize); }`

  Every IOP-side SID the game binds has no EE `g_rpc_servers` entry. Only `RPC.cpp:800` registers EE-side servers,
  and the only other reader is the debug panel (`ps2_debug_panel.cpp:955`). So every bind makes a placeholder, and
  every call **writes eight header fields into the placeholder** at `0x01F10000 + n*0x80` (`Helpers/Runtime.h:97-106`),
  not only the `buf` copy the PR names.
- **LATER.** In our layout the pool sits above the heap cap (`0x01F00000`) and below the main stack (#216 above), so
  no live game object can be there unless the stack overflows or something writes past `EndOfHeap`. The defect is
  latent. It becomes **TAKE at once** if the heap cap moves (#216) or the pools move.
- Test shape. It is the PR's own test, and it reproduces on our tree:
  - bind an unknown SID;
  - overwrite the returned `client.server` descriptor's `buf` with a victim address holding `0xA5` sentinels;
  - `SifCallRpc` with a 16-byte zero payload;
  - assert the victim is unchanged.

  Add a second assertion for our wider form: after the call, the 0x80-byte descriptor area is byte-identical to what
  the guest wrote.
