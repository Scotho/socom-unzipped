## 2. Where `sub_` comes from, and the default

- **In the csvs: 0.** No name in either csv starts with `sub_` or contains `sub_`/`SUB_` (A [2]).
- **In the sources** (A [2], the literal `"sub_` outside the SDK signature database): the analyzer's
  `function_classifier.cpp:130` (a name-reliability heuristic), and the recompiler's `elf_parser.cpp:30`
  (`IsAutoGeneratedName`: `sub_`, `FUN_`, `LAB_`, `DAT_`) and `elf_parser.cpp:216` (`MakeAutoFunctionName`,
  `sub_%08X`). The name is made in two places. The first is `:426`, a DWARF subprogram with no name, which
  never happens here because the retail ELF has no DWARF. The second is `:524`, `ScanJalTargetsFallback`.
  `parse()` runs it when the DWARF walk found nothing (`:1423`), and it makes one `sub_` function at every
  `jal` target.
- **What survives into `recomp/output`:** `loadGhidraFunctionMap` (`:959`, called from
  `ps2_recompiler.cpp:807`) appends the map's rows. It then erases every auto-named function whose start is
  not a map row (`:1069`) and keeps one function per start, putting a non-auto name first, then the larger
  `end`, then the name (`:1081-1102`). So a `sub_` survives only **at an address the csv already has as a
  `FUN_` row**, when the jal-scan's range runs further than the csv's. It is a placeholder for a csv
  placeholder. The peer's census of an `recomp/output` tree counted 6,750 `sub_` files
  (`tools_py/research/symbols/README.md`, `toml_overlap.py`). That count cannot be reproduced here: there is
  no `recomp/output`, and the toml's input `game/overlays/socom2_game.elf` is not on disk (stop rule).
- **`recomp/extra_functions.txt`** is not a source of `sub_` names (A [2]). It has 1,619 lines and 1,619
  distinct addresses, 1,475 of them with a `# imm target from …` note, and every one of them is already a
  row of the r0001 csv. It is the forced-entry-point list: `fix_ghidra_csv.py` folds any address that is not
  yet a row into the map as `FUN_%08x` (`tools_py/fix_ghidra_csv.py:78`). For r0001 that is 0 rows today.
  `extra_functions_r0004.txt` has 2,958 lines and 2,956 addresses: 2,950 are already rows and 6 would be
  added, also as `FUN_`.

**Decision: the default stands. `sub_` names get no sidecar row.** The mechanism above is the reason: the
recompiler makes them at run time from `jal` targets, they only ever sit on a csv `FUN_` address, and the
audit reads the csv, where there are 0 of them.

**A consequence the spec does not state.** A non-auto name at a start always wins that dedupe, and its csv
range becomes **authoritative** (`:603-606`). A function that starts inside an authoritative range is then
dropped (`:677-679`). So the rename is not only a filename change. For every renamed row whose output today
is a `sub_` with the jal-scan's longer range, the generated body shrinks to the csv's `[Start, End)`. The
dropping half is harmless for the 485: of the 1,097 csv rows whose range holds another row's start, **0** are
proposal rows (A [2]). Which of the 485 are emitted as `sub_` today needs `recomp/output`, which is not here.
The r0001 gate at the proof window is what settles it.

`carry_names.ADDRESSY` is `[0-9A-Fa-f]{8}` anywhere in the name. A [4] runs it, the proposed anchored rule

| set | names | 8-hex refused | proposed rule: auto | opaque-token |
|---|---|---|---|---|
| 485 proposals, mangled (`Proposed` column) | 485 | 4 (`…Fffffffff` float argument lists) | 0 | **1** |
| 485, `readable()` | 485 | 0 | 0 | 0 |
| 485, `readable()` + suffix where it collides (spec 1.2 rule 2) | 485 | **1: `C2DBitmapPoly_SetUV_ffffffff`** | 0 | 0 |

| 113 research/44 rows | 113 | 1 (`thunk_EXT_FUN_09481d98`, correctly) | 21 distinct (the `caseD_`s, `entry`, the thunk) | 0 |
| demo `.symtab`, readable + suffix where it collides | 9,703 | 9, among them `RTArray_Q23zdb6CDecal__*` (×5: "db6CDeca") and `…_1514c2dbitmap_poly_cpp_ctor` | 0 | 36 |

(A [4]; the demo lines need `game/demo_scus_972_05/SCUS_972.05`.)

The rule is also wrong in the other direction. **`caseD_<n>` is not addressy.** None of the 42 holds 8 hex
digits, although `carry_names`' docstring and spec §1.1 both say it refuses `caseD_…`. That is how 6 `caseD_`
names sit at a different address in r0004 (§1).

**Proposed rule change:** replace the unanchored run with the anchored shapes Ghidra and ps2recomp use for
placeholders. There are two predicates, because `entry` is a placeholder that names no address:

```
ADDRESS_NAME  = ^(?:(?:FUN|LAB|DAT|SUB|sub)_[0-9A-Fa-f]{8}|thunk_(?:EXT_)?FUN_[0-9A-Fa-f]{8}|caseD_[0-9A-Fa-f]+|switchD_[0-9A-Fa-f]{8})$
PLACEHOLDER   = ADDRESS_NAME or ^entry$
```

`carry_names` refuses `ADDRESS_NAME`, and the audit exempts `PLACEHOLDER`. It passes
`test_carry_names.IsAddressy`'s own vectors (5/5 auto, 6/6 real; A [4]). It classes 0 of the 485 readable
names, 0 toml names and 0 of the demo's 9,703 as auto, and it classes all 14,810 r0001 placeholders as auto,
which leaves exactly the 69 syscalls (A [1], "proposed auto rule"). It also makes the drop visible: today an
addressy name is skipped before counting, so `carry_names` reports `refused 0` while it loses a name (§5).

## 6. The format: CSV, one row per name, no comment header

- **Git diffs.** One row per line means a rename shows as a one-line diff next to the csv's own one-line
  change. The two `std` template names (`swap__Q23std30vector<b,…>`, `swap__Q210Metrowerks34cdeque<PCv,…>`)
  contain a comma (A [6], 2 of the 485), so `csv.writer` quotes those two `Mangled` fields and they still take
  one line each. JSON would put a record across many lines, or on one very long line.
- **Who reads it.** The recompiler never does: it reads only the toml's `ghidra_output`
  (`config_manager.cpp:41` → `loadGhidraFunctionMap`), and it splits on bare commas. That is a reason to keep
  `Mangled` out of `socom2_ghidra.csv`, and it is no constraint on the sidecar. The sidecar's readers are
  `carry_names` and the audit test, both Python with `csv.DictReader`.
- **No `#` header in the tracked file.** The proposals files (`game/demo_symbol_renames_7b.csv`) start with
  `#` lines, and `csv.DictReader` does not skip them: this note's script has to filter them by hand
  (`proposals()` in A). `recomp/socom2_ghidra.csv` has a column line and no comments (A [6]). Where each row
  came from is already in the `Source` column, so the sidecar gets a plain `Address,Name,Mangled,Pass,Score,Evidence,Source,Date`
  line and nothing else.
- **Nothing chokes on a file beside the csv.** `fix_ghidra_csv.py` reads its two arguments plus
  `merge_ranges.txt` beside the extras (`:84`). `scripts/build_revision.sh` and `build.sh:47` name their files
  explicitly. `overlay_repair.read_rows` reads a path it is given. No tool globs `recomp/*.csv`
  (`grep -rn "listdir\|glob" scripts tools_py | grep recomp` finds none), and `.gitignore`'s `/recomp/*.raw.csv`
  does not match `socom2_names*.csv`, so the file is tracked. The sidecar adds no column to the four-column
  map, so the recompiler's four-field reader (`elf_parser.cpp:959ff`) and `importGhidraMap` are untouched.
  There is one side effect: `build_revision.sh`'s step 2 `.repair.json` hashes both function maps, so the
  first build after a rename re-merges the overlay ELF once. The same file also uses the word "sidecar"
  for `<elf>.repair.json`, so the plan should say "the names sidecar" to avoid confusion.
- **The leak check refuses it as designed** (B): `socom2_names.csv:388: opaque-secret`. The cause is the
  `Mangled` value at 0x0038b250, `SetButtonState__Q221@unnamed@zui_skb_cpp@12CSkbKeyProps…`, where the `@`
  breaks the token, so the `__` exemption no longer applies. `readable()` output alone gets 0 hits (A [4]).
  The later passes will hit it more often: 156 of the demo's mangled names trip the same rule (A [4]).
  **Task 1 needs one reviewed allow line**, e.g.
  `opaque-secret  recomp/socom2_names*.csv  @unnamed@  # a Metrowerks mangled name's anonymous-namespace path`,
  or a rule that exempts the `Mangled` column. Without one, pre-commit refuses the commit.

## 7. The audit prototype

The rule: every csv row whose `Name` is not a `PLACEHOLDER` has exactly one sidecar row with the same `Address`
and `Name`. A sidecar row whose `Address` is not in the csv, or whose `Name` disagrees with it, fails.

There is no sidecar today, so A [7] prints the backfill instead. The spec's literal prefix list gives **70**
rows, because it misses `thunk_EXT_FUN_`. The anchored rule gives **69**, not 113. `A --rows` prints all 69 in
the order `Address,Name,Mangled,Pass,Score,Evidence,Source,Date`. For example:

```
0x001a3720,SetGsCrt,,ghidra,1.00,"EE kernel syscall stub, 16 B (li v1 + syscall); the Ghidra export's name, in the csv since f69790b",scripts/ghidra_export_functions.sh; research/48 [3],2026-09-04
0x001acfa0,RFU091,,ghidra,1.00,"EE kernel syscall stub, reserved slot, 16 B; the number in the name is the one it loads; the Ghidra export's name, in the csv since f69790b",scripts/ghidra_export_functions.sh; research/48 [3],2026-09-04
```

The audit must key on `Address`. `Name` is not unique: there are 3 duplicated syscall names over 10 rows (§1).

## The sidecar, decided

- **File:** `recomp/socom2_names.csv`, plus `recomp/socom2_names_r0004.csv` written by `carry_names`.
- **Columns:** `Address,Name,Mangled,Pass,Score,Evidence,Source,Date`, as the spec has it. `Address` is
  `0x%08x`, and there is one row per address.
- **Format:** CSV. The first line is the column line and there is no `#` header. Fields are quoted only where
  `csv.writer` needs it (2 of the 485 `Mangled` values).
- **The audit rule, in one sentence:** every row of `recomp/socom2_ghidra.csv` whose `Name` is not a
  placeholder (anchored `FUN_/LAB_/DAT_/SUB_/sub_`+8 hex, `thunk_(EXT_)FUN_`+8 hex, `caseD_<hex>`,
  `switchD_`+8 hex, or `entry`) has exactly one sidecar row with its `Address` and `Name`, and every sidecar
  row names a csv address whose `Name` it matches.
- **Backfill:** **69 rows**, not 113, all `Pass=ghidra, Score=1.00, Date=2026-09-04,
  Source=scripts/ghidra_export_functions.sh; research/48 [3]`. The `Evidence` is one of three texts (§3):
  52 EE kernel syscall stubs, 8 SIF syscall stubs and 9 reserved-slot stubs.
- **`sub_`:** no rows (0 in either csv, and the recompiler makes them at run time on `FUN_` addresses).
- **The carry rule:** `ADDRESS_NAME` replaces the 8-hex run, and a dropped name is counted.
