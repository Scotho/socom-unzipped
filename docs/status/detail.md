# The status map, in detail

![The status map](map.svg)

Generated by `python -m tools_py.status_map` from `docs/status/status.toml`; do not edit by hand (edit the
data file and regenerate; `--check` fails while this file or `map.svg` is stale). Statuses are read from
`docs/KNOWN.md`, which wins on any disagreement. *Working* counts towards the percentages; *Partial* and
*Pending* do not.

**The status rule.** *Working* (ok): works in the game with no open defect or known divergence recorded in
`docs/KNOWN.md` or `docs/LATER.md`; being unverified against a console does not make a row partial on its own, and
the note says so where it applies. *Partial*: an open defect or a known divergence. *Pending*: not modelled.

**What the libraries panel leaves out.** Only the loader `SCUS_972.75` is counted. The Sony code linked into the
game image itself is not: the libnet EE wrappers (0x245690-0x2484a0, research/10), the lgAud headset client, the
989snd `snd_*` client and the `sceInet*` calls, among others. The loader's own code (its `main()`, the "mp_net"
BSD-socket shim of research/10) is the game's, and zlib 1.1.4 is a third-party library; both are left out too.

**The hardware weights** are a rough share of the work each component asks of a PS2 recompilation and its runtime
(the CPU 5; the kernel, GS, VIF1/VU1 and SPU2 3; most others 2; the timers and USB 1). They are judgement calls, as
in the map this one follows, and they decide only the size of a rectangle and the hardware percentage.
